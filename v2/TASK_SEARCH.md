# TASK_SEARCH: switch-task lane (2026-11-07/08). DEV DATA ONLY. No locked/S2 row was read or scored.

Goal of the lane: find the commercial-class task whose real native output (short label word) is most robust under ~1.6-2.0 bits/weight, so that rule 2 (keep >=98% of base-correct items, >=95% per class) is reachable. Everything below is measured with the repo quantizer (`research/C_tasks/dense_c.py`, copied to `task_search/dense_core.py`: Hadamard rotation + GPTQ + entropy-coded L-level grids, per-module Lagrangian allocation, real `target_ratio` allocator, no optimizer, no backward) on Qwen2.5-7B/14B/32B-Instruct, with 12 tasks x (S1-role + S3-role source) x ~600 items per task. Native output = the label word (or tool name) + `<|im_end|>`; an item is correct iff every answer token is the argmax, which is exactly "greedy generation reproduces the gold string" (no letters, no option rows, full lm_head). Retention = P(candidate correct | base correct). Wilson 95% lower bounds in brackets where shown.

## 0. Bottom line (read this first)
1. **No task passes rule 2 at <=10% of fp16 on 7B, 14B or 32B**, and no task passes at 12.5% on 14B either. The best realistic-data result at 10.03% of fp16 is Qwen2.5-32B: NEWS-topic 0.961, INJ (tournament dev data) 0.957, ROUTE 0.947, FIN 0.937, TOOLSEL 0.928. Only the easy-data INJ probe (safe-guard + jackhhao, sources that `tournament/INJ` dropped for licence/leakage) reaches 0.981 / 0.989 on 32B, and that does not survive the move to the real INJ dev sets (0.957 / 0.958 / 0.942).
2. **Switching task is worth about +-2 points; it does not close the 98% gap.** Task choice moves 32B retention at 10.0% between 0.83 and 0.98; the two binary/few-class tasks with high base accuracy are at the top, but on realistic data they all sit at 0.93-0.96. Quantizer noise between two draws of the same recipe is already about +-2 points (INJ-real 32B: 0.957 / 0.958 / 0.942 at 10.0 / 11.3 / 12.5%, non-monotone).
3. **Large base margin is not what buys retention here.** Base-correct median margin is 10-12 logits for almost every task (saturates), so it does not separate tasks. Retention by base margin on 32B at 10.03%: margin [10,12) (n=3732) keeps 0.960, [12,16) 0.961, but [6,8) 0.798 and [0,2) 0.751; at 14B the [10,12) bin keeps only 0.820. Even the most confident items lose 4% (32B) to 18% (14B) because the noise std at 1.5 bpw (7-13 logits on 8B/14B, `research/C_tasks/REPORT.md`) is the same size as the margin. 64% of 32B failures at 10.03% come from items with base margin <10; 32% from margin <6. Items that the base is very sure of are not safe.
4. **Bits and base size dominate.** For every task, 14B -> 32B at 10.03% adds 4 to 20 points (TOOLSEL 0.881 -> 0.928, INJ-real 0.912 -> 0.957, NEWS(6-menu) 0.850 -> 0.965); 10.03% -> 12.5% adds 1 to 12 points. A 7B base is hopeless on every task (best 0.90 INJ).
5. Rule-8/3 killers found: EMOTION (rare classes `fear`/`surprise` collapse; surprise has <600 train rows), INTENT (60 classes, no way to lock 300/class), ROUTE (29 classes, same), LANGID (base 0.988 = ceiling, class `Portuguese` collapses at 10.0%), HALU/BTSAFE (base 0.75-0.84 but weakest retention of the binary tasks).
6. Recommendation: see section 4. Top 2 = **NEWS-topic routing** (new; dev split + hash plan built in `task_search/NEWS/`) and **INJ prompt-injection detection** (existing tournament lock; best-known category). Neither passes today; this lane did not find a task that removes the compression problem. The cheapest remaining levers are base size (>=72B, evidence in D_scale: 95.5% real-exam TOOLSEL at 9.6%) and seed/draw selection on dev (+-2 pt), not task choice.

## 4. Recommendation
**Top 2 tasks:**
1. **NEWS-topic router (World/Sports/Business/Technology).** Highest 32B retention among tasks that can satisfy rules 3 and 1 on paper: 0.961 / 0.962 / 0.979, overall Wilson lower bound 0.950 / 0.950 / 0.970; 4 classes with huge pools; the other-source blocks are natural (HuffPost 2012-22, BBC 2004-05 vs AG 2004-05 wire); base 0.868 on 32B (well above 0.25 chance, below ceiling); output is one word. Risks: (a) Technology class floor 0.86-0.94 < 0.95 in every draw, (b) "toy/benchmark" optics (rule 9): AG News is a classic benchmark; argue as publisher content-routing / tagging, S2 is production-style headlines, (c) AG/BBC licences are research-only, HuffPost is CC-BY-4.0, (d) feedback story (rule 5) needs a NEW label word (Entertainment): planned in section 5, untested.
2. **INJ prompt-injection / jailbreak detection**, tournament lock (already built, 2320 items, cells >=330). Retention is lower on the real data (32B 0.957 / 0.958 / 0.942) because of the S2-benign cell (0.73-0.91, noisy community labels, base itself weak there) and the S1/S3 injection cells (0.88-0.99), but it is the most commercially legitimate label task, it is built, and the base is solidly above chance. Needs the 98% / per-cell 95% gap closed by +4 pt overall and +20 pt on S2-benign.
Backup: FIN (0.971 / 0.975 at 11.3 / 12.5% on 32B, worst class 0.96) but narrow-domain and thin second source. Rejected: LANGID (ceiling), EMOTION / INTENT / ROUTE (class counts), HALU / BTSAFE (retention <=0.91 at 11.3%), TOX (S2 data quality; already has its own lock), TOOLSEL (rule 7 baggage).
**Do not expect either top task to pass at <=10% on <=32B.** Realistic route to rule 2: base >=72B (D_scale: 95.5% TOOLSEL / 95.2% INJ real-exam at 9.6% is still short), better quantizer (vector / trellis codebooks; seed ensembling; our draw noise is +-2 pt), or both. Task switching alone is not a path.

## 5. NEWS: dev split and locked-exam construction plan (nothing locked, nothing scored)
Directory `v2/task_search/NEWS/`: `build_news.py` (deterministic; `dev` mode only, `locked` mode intentionally not implemented), `HASH_PLAN.json`, `DEV_SHA256.json`, dev items (`s1_dev` 600, `s3_dev` 600, `s2probe` 400, `calib` 1000, `items_dev` = concatenation of the three eval files), feedback files (`fb_annot_25`, `fb_teach_unseen_200`).
- Task: input = one article (title + description); output = the model GENERATES one word from {World, Sports, Business, Technology}; strict exact-string scorer (whole output, trimmed, equals the label; anything else wrong). Same prompt for base and artifact; no letters, no option rows, no constrained decoding.
- Group-safe split: bucket = sha256('news-split-v1|' + first-12-normalised-words) mod 100 (wire reprints and duplicates share a bucket; exact-normalised-text dedupe first). AG (127,361 rows after dedupe): [0,60) pool/calib/feedback, [60,70) S1 dev, [70,80) spare, [80,100) locked-S1 candidates. HuffPost (19,348 rows in the 4 classes): [0,10) S2 probe (rule-8 health check ONLY), [10,20) spare, [20,100) locked-S2 candidates. BBC (1754 rows, tech/business/sport/politics->World) is the S3 OOD dev proxy: used for tuning of compression and feedback hyper-parameters, never in the lock.
- Locked-eligible candidates (label counts only; text not read): AG Business 6278 / Technology 6351 / Sports 6317 / World 6255; HuffPost World 6561 / Technology 1555 / Sports 3301 / Business 4112. Feasible: **locked = 8 cells (2 sources x 4 classes) x 400 = 3200 items** (>=300 per class overall and per (source x class) cell, 1600 from a source never built/tuned on, >=500 required), chosen by sorting each cell's candidates by sha256('news-lock-order|' + id) and taking the first 400. No sampling beyond that, no backfill. Cell shortfall aborts the build.
- Lock procedure (to be run by the harness, not now): `LOCKED_BUILD_OK=1` after the artifact is frozen; commit a manifest with sha256 of the file and of the sorted `id|answer` list BEFORE scoring any model; locked file chmod 444 on a Modal volume (as `tournament/INJ`); raw dataset revisions pinned in the lock (ag_news eb185aad, news-category-dataset 304a05a5, bbc-news 9c31f708).
- Weaknesses to state in the proof: AG/BBC/HuffPost label noise (HuffPost WORLD NEWS vs POLITICS boundary, AG Business/SciTech boundary); S3 (BBC) and S1 (AG) are both 2004-05 news; HuffPost class `Technology` is the smallest S2 cell (1555 eligible); topic classification is a benchmark-shaped task (rule 9 risk).
- Feedback plan (rule 5/6, untested): new label `Entertainment` (HuffPost ENTERTAINMENT, 13,538 rows, outside the menu) taught with <=25 annotated items (`fb_annot_25`, hash-ordered from the non-locked bucket <20), measured on >=25 unseen items (`fb_teach_unseen_200`, same bucket); neighbours = base-correct World/Sports/Business/Technology items in s1_dev + s3_dev touching the same lexicon; controls = shuffled labels and empty feedback. The label word is multi-token, so this tests the mechanism on a real new class; rule-4 (no prompt edits, no fitted heads) compliance must come from the feedback mechanism, which this lane did not build.
- Rule 8 evidence on this exact build: base accuracy by source (32B bf16, teacher-forced/greedy-equivalent): AG 0.867, BBC 0.875, HuffPost-probe 0.860 (14B bf16 0.875 overall).

## 6. Caveats
- Single draw per (model, ratio): GPTQ uses random Hadamard signs; two draws of the same recipe differ by ~2 pt (INJR 32B 11.3 vs 12.5%). Wilson intervals treat items as independent and ignore draw noise.
- "1.6/1.8/2.0 bpw" in the request is approximated by `target_ratio` 0.100 / 0.1125 / 0.125 (body bpw 1.56-1.58 / 1.78-1.79 / 1.94-1.98). All 32B points are at or above the 10% cap (10.03% is 0.03 pt over); the cap-compliant 0.096 point was run on 7B and 14B only.
- Probe items are class-balanced 300+300 per task and one zero-shot prompt per task. Retention is on the same items for every bit-rate (not independent across bit-rates).
- INJR S2 items come from the tournament `audit_S2` slice (QA only there), 200 injection + 200 benign; they are not the locked S2 block.
- Models: Qwen2.5-{7B,14B,32B}-Instruct only. Qwen3 numbers for the same pipeline are in `research/C_tasks/REPORT.md` (8B/14B) and D_scale.
- The exact-build NEWS (4-menu) was run on 32B only: the 14B relaunch sat in the Modal queue (workspace at the 10-GPU cap) and was cancelled; 14B evidence for NEWS is the 6-menu probe (row 1b).
- Cost: Modal only, `--detach`, apps `tenpct-tasksearch` (volume `tenpct-tasksearch`); estimated spend ~ $50 of the $75 cap (A100-80GB for 7B/14B, H100 for 32B; one 32B job OOMed on the GPU-resident quantizer and was rerun with CPU-resident layers). No Vast, no AWS boxes.
