# FEEDBACK_LEGAL: strongest rule-4/5/6 feedback mechanism we could build and test (2026-11-08)
Code/results: `v2/fb_legal/` (`legal.py` Modal app tenpct-fblegal, `analyze*.py`, `results/*.json`, `data_tox/`). Dev data only (TOX s1/s3 dev+pool, Aegis train for the new class; locked rows and the filed issue untouched). Compute ~ $6 of Modal A100-80GB.

## 1. Reading of the rule text (what is and is not defensible)
- Rule 4 bans ADDED things: heads, classifiers, adapters, side memory "the system looks answers up from", feedback in the prompt; "the answer has to come from the original model's own computation". The filed C2 head.npz + prototype memory is exactly that. Any mechanism that stores statistics/vectors outside the weight tensors and consults them at inference is out (also steering vectors, logit-bias tables, kNN).
- "No weight training" (README intro, maintainer q2/q3 "no retraining of the weights"). A closed-form edit is not gradient training, but a maintainer can read "fitting weights to annotations" as retraining. This is the residual risk; no feedback mechanism that changes behaviour has zero risk. Ladder: (1) requantization with feedback as extra calibration inside the same compression run = most defensible but cannot teach (see 3a); (2) closed-form edit of existing rows, no gradient, no added bytes = what we ship/test; (3) anything looked up = banned.
- Disclose plainly: weights are NOT frozen after feedback (two or three lm_head rows change). Empty feedback leaves every byte identical (the update is a pure function of the annotations).

## 2. The mechanism (`mnH`, closed form, 0 bytes added)
Inputs: <=25 annotated items (user marks the base's own mistake and writes the correct label; the new label may be a string the prompt never mentions). Steps: teacher-force the corrected answer through the ORIGINAL model; at each answer position where the model's argmax differs from the annotated token t, take the final-normed hidden state h_i. For each such target token t (a row of the EXISTING lm_head) compute the minimum-norm change in the metric of the model's own calibration Hessian M = E[h h^T] (second moment of the same unlabeled calibration inputs and the model's own greedy outputs that the compression run already uses for GPTQ/Hessian rounding; labels never used):
  delta_t = M^-1 H^T (H M^-1 H^T + lam I)^-1 g,   g_i = (best competitor logit - current logit of t at site i) + m,   m = 8 (one constant, same for all models/tasks).
  row_t <- row_t + delta_t, written in place. No gradient, no optimizer, no new tensor, no stored annotation, no lookup, no prompt change. Compared with the earlier lm_head edits (feedback_v3) the difference is that the direction is not a class-mean/LDA discriminant with label-tuned alpha: it is the smallest change (in calibration-Hessian norm) that makes the annotated corrections come out, so ordinary calibration inputs keep their logits.
Rule-4 risks (stated, not argued away): (i) it is "computation fitted to data" in the weak sense that the new row values depend on the annotations; (ii) M comes from calibration data (as GPTQ's Hessian does); it is not stored in the artifact, it is recomputed by the feedback command from calibration texts that must then ship (cost: calibration set bytes, <=0.5 MB) - not yet counted in an artifact; (iii) a maintainer who equates "fit a linear direction to few labels" with a classifier head will reject it.

## 3. Alternatives tested, and why they lost
(3a) Annotation-aware requantization (priority-1 rung). Adding <=25 items to the calibration/Hessian of the same GPTQ run only re-weights rounding error on those inputs; it cannot install a label the model ranks ~30 logits below, so we did not run a fake version. The honest variant is "round the edited row onto the grid": that is `mnH` followed by re-quantization of the touched rows (section 5): same bits, +0 bytes. This is rung 2 in disguise, not rung 1.
(3b) Mean-direction row nudges (`hebb`), whitening with only the annotated items' own prompt statistics (`swh`), per-row scale (`scale`): all teach (hebb/swh teach 0.8-1.0 on Qwen3-8B TOX) but leak onto everything: retention of base-correct neighbours 0.00-0.33 (hebb, swh) and 0.37-0.8 (scale). Shuffled-label control for hebb teaches as well as real (0.94-0.98) = no specificity. Useless. (`results/*_round1.json`)
(3c) Natively 1-bit Bonsai-8B (prism-ml/Bonsai-8B-unpacked, every weight is +-scale per 128 group, lm_head included). Edits must be sign-bit flips (scales unchanged). (i) `mnH` + flip-only re-binarization with the scale-up gamma search: 50% of annotated sites reach the margin with ~2300 of 4096 bits flipped per row, teach 0.00, neighbours 0.78-0.90. (ii) z-score greedy bit flips (gain on annotated mean / damage on calibration second moment, up to 2048 flips): never reaches the margin, no flips applied, teach 0.00. (iii) `hebb` + binarization: annotated sites 100% fixed, teach 1.00 but shuffled labels also 1.00 and neighbour retention 0.00. => NO selective feedback on a 1-bit lm_head was found. Reason: the new label starts far below the competitors (gap tens of logits) and a row of +-s weights has no small step; every realisable change is large and non-selective. (The first bonsai_tox_b run, which shows retention 1.0 / teach 0, was produced by code that did not flip bits; superseded by bonsai_diag/diag2/flip/flip2, whose instrumented logs record flips and site_ok.)

## 5. Survival of the edit in a quantized artifact (the old objection)
Qwen3-8B, lm_head RTN g128 (3 and 4 bit, with and without a Hadamard-128 rotation), edited rows re-encoded at the SAME bit width (no new bytes) or at 8 bit (+~2 KB per row). Quantized base teach 0.00. After the edit (m16, n=12, 8 draws): 4-bit 0.376 same-bits vs 0.401 fp rows; 3-bit rotated 0.374 vs 0.390; 3-bit unrotated 0.391 vs 0.346. Qwen2.5-7B (m8): 4-bit 0.720 vs 0.727; 3-bit rotated 0.719 vs 0.740. So with the Hessian-metric edit the gain is NOT rounded away (the old lda edit was). Neighbour retention (vs fp-base-correct) equals the quantized base's own level (0.96-0.98) to within noise. Shuffle control stays <=0.13. Files `results/*_quant.json`, `analyze_quant.py`.

## 6. Verdict
- Rung 1 (requantization with feedback in the calibration): cannot teach anything; not a mechanism.
- Rung 2 (`mnH`, this file): the only variant that passes the behavioural parts of rules 5/6 on a 7-8B-class generative label task with natural errors: clear gain on 56 unseen items (+0.5 to +0.8), shuffled and empty clearly worse (+0.47 to +0.68 over shuffled), neighbours 99.8-99.96% kept with every cell >=98.6%, 0 bytes, survives 3/4-bit requantization. Whether it passes rule 4 is a reading the maintainer decides: no head/adapter/memory/prompt is added, but the weights do change by a closed-form fit to the annotations. We rate it the best available, still gray.
- 1-bit native (Bonsai): no selective feedback mechanism exists in the sign-bit format; do not rely on feedback there.
- Next steps if adopted: package as `feedback.py` (calibration texts shipped and counted), run harness v3 arms on a T1/TOX new-label scenario, repeat with 10+ draws on the real compressed artifact, add Qwen2.5-7B INJ/SENT scenarios, fix the INJ collapse by adding the continuation positions of all old-label outputs to M.
