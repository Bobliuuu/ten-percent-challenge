## Selection-by-labels is a head
Any rule of the form "keep exactly the tokens/neurons that the task labels use" is a new fitted computation (it is a classifier cut out of the model) and violates rule 4/7/9. All selections here use only (a) activation statistics on unlabeled calibration text, (b) a block-influence score, (c) a label-free token-id rank. Task-source calibration text is used only as unlabeled input stream (the answer string is part of the stream for the chat template, exactly as for the GPTQ Hessians already used by every other entry in this repo).

## Does task-fitted pruning risk the maintainer's different-distribution check?
Yes, in a measurable way, and we measure it: calibration is source S1 only (INJR: PromptShield; NEWS: AG News); evaluation is S3 (deepset+gandalf / BBC) and S2-probe (JailbreakHub / HuffPost), which the calibration never saw. Per-cell retention on S3/S2 versus S1 is the explicit different-distribution hit. Pruning that drops S3/S2 cells below S1 cells is evidence of calibration over-fit and would be rejected by a different-distribution check even if S1 passes.

Rule 9 reading: pruning that removes capacity the commercial task does not use is the textbook meaning of task-specific compression, so it is not spirit-defeating by itself, as long as (i) the task remains broad (prompt-injection detection over any text, news-topic over any article), (ii) the artifact still does open text generation, and (iii) the maintainer's own data from another distribution still gets answered by the same ordinary decoding.
