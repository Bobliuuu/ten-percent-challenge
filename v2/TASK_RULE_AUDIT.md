# TASK_RULE_AUDIT: does each primary task satisfy the rules? (2026-11-08, hard gate)

Gate: only a task with NO FAIL cell can be primary; GRAY cells are listed honestly with what would make them PASS. Counts are from the dev/pool builders (`task_search/EASY/PLAN.json`, `PLAN2.json`, `task_search/T3/PLAN*.json`); nothing locked was read. "pool" = all rows of the public source after exact-text dedupe; "strict" = rows in hash bucket [70,100), never used for dev/calibration in the EASY builds (that slice is only ~30% of the pool); "free" = pool minus dev minus calibration rows (what a sealed exam could draw from if tuning is restricted to the other source).

How R3's "never used source" bites: the >=500 items must come from a source or period we **never built, tuned or calibrated on**. The EASY dev and calibration files use BOTH sources of every task, so as built NO EASY task has a never-used source. To pass, rebuild with ONE source as the only tuning/calibration source (S1) and **seal the other (S2) completely** (no dev, no calibration, no feedback items from it). The tables below say which source would be sealed and whether it is big enough. R2 reading used: >=300 locked items per answer class pooled and per source with >=500 for the sealed source; the 95% per-kind gate is then estimable (300 items allow 15 misses).

Legend: PASS = rule met by counts/argument; GRAY = met only under a stated assumption or with a disclosure; FAIL = cannot be met with the sources we have.
