# gptaq_fix: what was wrong with `tgt`
Failure: `tgt` runs (vq8_k13p5_tgt: ppl 607, KL 4.46; tgt2 with damp 0.1 / alpha 0.5: ppl 135, KL 3.0) vs the same recipe without tgt (ppl 12.6, KL 0.54).
Cause (analytic): implemented target Wt = W Hfq (Hq + lambda*mean(diag) I)^-1 where Hfq = X_fp^T X_q. When X_fp = X_q (layer 0, or any layer with no upstream error) Hfq = Hq and Wt = W Hq (Hq+lambda I)^-1 != W: a spectral shrinkage of every direction with eigenvalue below lambda*mean(diag). With massive-activation Hessians this deletes most of the weight. Tf32 accumulation of Hfq vs Hq was a second, smaller issue.
Fix: residual form Wt = W + alpha * s * W (Hfq - Hq)(Hq + lambda*mean(diag) I)^-1 (GPTAQ's  W dX X_q^T H^-1 term), s = min(1, bound/(||dW||/||W||)), bound 0.25, fp32 accumulation, per-tensor `tshift` log line (rel, scale). Identity when dX=0.
Result of fix (7B, K=14500, 1 seed, dev real generation; baseline INJ 94.9 / TOOLSEL 93.6 / KL 0.537): lambda .03 alpha .5 -> INJ 90.1 / TOOLSEL 92.7 / KL 0.773; lambda .01 alpha 1.0 -> INJ 62.3 / TOOLSEL 84.7 / KL 1.004. No collapse any more (identity fixed) but worse than baseline, monotone in alpha; non-harm criterion FAILS, so GPTAQ is dropped from the stack on this evidence (only 2 grid points, INJR-dev and 3 seeds not run; a smaller alpha like 0.1-0.25 would trend toward baseline and is untested). Status: implemented in qpush.py (cfg tgt=true, tgt_damp=lambda, tgt_alpha=alpha, tgt_bound). 7B validation runs vq8_k13p5_gptaq_l01_a1 and _l03_a05 were launched (cfgs_gptaq.json) but had not run when this was written. X02 numerics acceptance, INJR-dev 3-seed grid and decision rule were NOT executed; GPTAQ therefore stays UNVALIDATED.
