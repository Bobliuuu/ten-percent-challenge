# QUALITY_PUSH: training-free VQ quality at <=10% (Qwen2.5-7B-Instruct, dev only)
Status: written 2026-11-08; 32B VQ row and GPTAQ-fix rows PENDING at time of writing (see end). Code: `v2/quality/qpush.py` (Modal, detached), `alloc.py`, `analyze.py`, `report.py`; raw per-item results `v2/quality/results/*.json`.

## Setup (what the numbers are)
- Quantiser: random-sign + Kronecker/Hadamard incoherence on both sides of every linear, sequential block-LDLQ with Hessian from quantised-prefix activations, D-dim Gaussian k-means codebook shared by all layers and tensors (D=8, K=2^13..2^16; D=1,K=3 = scalar baseline). One fp16 scale per tensor. No gradients, no fine-tuning, no learned rounding/rotations.
- Bases: Qwen2.5-7B-Instruct (base INJ-real acc .873, TOOLSEL-real acc .808), Qwen2.5-32B-Instruct (base INJ .794, TOOLSEL .806). Real greedy generation with strict scorers `research/D_scale/real/*_scorer.py` on `inj_items.jsonl` (1566) and `toolsel_items.jsonl` (1063), vLLM 0.11, bf16.
- Retention = kept / base-correct (same items); cell = (source/role, kind); lower bound = Wilson 95% (item level, no cluster correction). General gate = MMLU/ARC-C/HellaSwag/TruthfulQA-mc1, n=500 each, retention of base-correct (harness/validity/general_remote.py prompt).
- Size = (fixed-length index bits + codebook + per-tensor scale + norms/biases + estimated 24,176-row 4-bit g64 embedding AND lm_head + 6 MB tokenizer/config/code) / fp16 bytes. This is an ESTIMATE, not a packed file; entropy coding of the indices saves only 0.005 bit (k-means index histograms are near uniform).
- Embedding/head: 4-bit g64 RTN fake-quant applied to both in all quantised runs (full vocab in eval; vocab pruning itself not simulated, its legality per RULES C6/queue: label-free trim is DROPPED as gray).
- Calibration (CAL): `research/D_scale/modal/calib_ct.jsonl` (598 S1-role items of the label tasks, chat-rendered with the gold answer) + 299 tool-call transcripts (t1v2) + `gen_tokens` of generic wikitext-103 train text. These share SOURCE DATASETS with the S1-role eval items (ids disjoint). Config selection among the 7B variants below was done ON the same eval items, so every 7B number is a dev number with selection optimism, NOT a REP/locked number (RULES checklist 3/4 not satisfied; gate-grade only). Noise: n~1300 base-correct => one-sigma about 0.7 pt; run-to-run (calibration/seed) differences below ~2 pt are noise.

## Findings
1. VQ beats scalar at equal bytes by a wide margin: 8-dim K=8192 (1.625 bpw, 9.36%) vs scalar 3-level Lloyd-Max/LDLQ (1.585 bpw, 9.15%) with identical calibration: INJ 92.2 vs 70.1, TOOLSEL 93.8 vs 79.9, KL 0.70 vs 1.30, wikitext ppl 14.6 vs 25.7 (base 8.29).
2. Calibration quantity and mix are the largest lever found: 131k task tokens only -> 1M-token mixed (k13): KL 1.11 -> 0.70, INJ 87.0 -> 92.2, TOOLSEL 92.1 -> 93.8. Going to 4M tokens with the task share diluted to 3% lowers KL slightly (0.67) but task retention drops sharply (INJ 77.8, TOOLSEL 85.2): task-matched share matters, not just token count. Task share 30% (g300k) gives the best INJ (96.2) but lower TOOLSEL (92.3); repeating task data x3 is neutral.
3. Bytes: at the 7B limit (K=14500, 1.728 bpw, 9.91%) we reach INJ 94.9-96.2 / TOOLSEL 92.3-94.3 (worst cell 77-94). 2.0 bpw (11.4%, over budget) gives 94.5 / 94.5, i.e. the 7B ceiling for this training-free method is about 94-96 even at 2 bits. No 7B configuration passes 98% overall / 95% per class.
4. NULL results: KL-sensitivity per-group K allocation (alloc.py, sens measured per layer x {qkv, o, gate/up, down}, predicted -20% KL) gave KL 0.580 vs 0.537 for uniform at equal bytes (INJ 90.9 vs 94.9): no gain, within noise or worse. Hessian damping 0.003 / 0.1 and scale multiplier 0.95: no gain. Entropy coding of VQ indices: 0.005 bit. Sensitivity measurements: gate/up are the largest absolute KL contributors (0.60 of 1.21 summed), per-parameter attention is ~3x more sensitive; first layer MLP most sensitive. The per-tensor KL sum (1.21) matches whole-model KL at k13 with wiki calibration (1.11), so group KLs are additive, but the optimum predicted from them did not materialise.
5. GPTAQ-style target (`tgt`): first two implementations destroyed the model (ppl 607 / 135). Diagnosis (code review, not yet confirmed by a log): the target was Wt = W Hfq (Hq+lambda I)^-1, which for dX=0 equals W Hq (Hq+lambda I)^-1 != W, i.e. a lambda-dependent shrinkage of every low-eigenvalue direction (lambda=0.1*mean diag is huge under massive activations). Fix in qpush.py (commit "GPTAQ residual-form target"): Wt = W + alpha*s*W (Hfq - Hq)(Hq+lambda I)^-1 with a per-tensor relative-norm bound s=min(1,0.25/||dW||/||W||), exactly W when dX=0, fp32 (no TF32) accumulation of both Hessians. Validation runs `vq8_k13p5_gptaq_*` (cfgs_gptaq.json) were queued on Modal; results below if present.
6. Scale (bigger base): the 32B VQ run at k13 (1.625 bpw, 9.89%) quantised in 9.4 ks on 2xA100 (relerr 0.0133). Wikitext ppl 11.88 vs base 5.58 (2.1x; 7B k13 g1M: 1.76x), i.e. perplexity damage did NOT shrink with scale at this calibration size (500k tokens, 1024 seq). Real-generation retention of the 32B artifact: PENDING (two attempts lost to a vLLM memory leak; third queued).
7. Prior comparators in repo (ECSQ, same items): Qwen2.5-72B @9.6% TOOLSEL-real best 95.55 / INJ-real best 95.21 (D_scale REPORT). 7B VQ at 9.9% (94.9 INJ / 93.6-94.3 TOOLSEL) is within 1-2 pt of the 72B ECSQ result at the same bytes, i.e. VQ is worth roughly a 10x larger base under scalar quantisation. VQ at 72B was NOT run (budget).
8. MoE and pruning were not re-run here; see v2/prune/RESULTS.md and v2/moe/RESULTS.md, research/L2_moe/REPORT.md (best fitting MoE points ~0.93-0.94 retention). Layer drop / head pruning were not combined with VQ.
