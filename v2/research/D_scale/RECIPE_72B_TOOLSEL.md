## (0) IMPORTANT caveats for whoever builds the real artifact
1. **The "size" 13,972,214,186 B (ratio 0.096087 of 145,412,407,296 B fp16) is an ACCOUNTING number, not a file.** Per tensor: n * (H*1.005 + 11/g) bits where H = empirical entropy (bits) of the L-level code histogram of that whole module (order-0, one histogram per module) and 11 bits per group of g=128 for the scale. The shipped scratch format is NOT entropy coded: codes are stored 2 per byte (4-bit nibbles) and scales as fp16 (16 bits), 39 GB on disk. A real artifact must (i) implement the order-0 (per module) rANS coder, meeting 1.005 x entropy, and (ii) store the group scale in <=11 bits (the pipeline assumes an 11-bit scale code; the evaluated model used the fp16 values, so you need to verify that quantising log2(scale) to 11 bits (or equivalent) does not change results; this has NOT been tested). Also count tokenizer/config files (0.45 MB), norms/biases (11.47 MB bf16) and the decoder code (accounted 150 kB).
2. Embedding and lm_head: their codes were NOT saved, only the dequantised bf16 tensors (`emb.pt`, `head.pt`). They are on an 8-level grid after rotation (group 128 along the hidden dim, sign vector seeds below); you can recover codes by re-rotating and rounding to the nearest grid point (error << grid spacing), or re-run the embedding/head quantiser (deterministic RTN for emb, GPTQ with the final-norm Hessian for head).
3. The evaluation base was an fp8-dynamic 72B and the candidate was re-quantised to fp8-dynamic for vLLM (72B bf16 = 145 GB does not fit one GPU). 
4. Order of selecting this recipe among variants used the dev items themselves (one-shot comparison of ~6 recipes), so the 98.3% is a dev number with mild selection bias.

## (a) Quantiser and allocation
* Code: `~/ten-percent/v2/research/D_scale/dense_stream.py` (mode `quant`), config used (also `artifacts/` and on g14 `/opt/dlami/nvme/work/D_scale/M72_V3_gam1_ncal256_emb8_lcm.json`):
  `{"tag":"Qwen2.5-72B","mode":"quant","emb_L":8,"head_L":8,"g":128,"target_ratio":0.096,"name":"V3_gam1_ncal256_emb8_lcm","gamma":1.0,"ncal":256,"calib_ct":".../calib_ct.jsonl","calib_ct_mix":true,"t1dir":".../t1v2"}` (defaults: CL=512, damp=0.01, scale_bits GB=11, no layer dropping, no act-order).
* Per-module level map (L = number of uniform grid levels; 2=1 bit, 3=1.58, 4=2 bit ...): **`artifacts/lmap_V3.json`** = {layer: {tensor: {"L":..,"shape":[R,C]}}} for all 80 layers x 7 tensors. Summary of L counts over 80 layers: q_proj {2:39,3:38,4:1,5:1,8:1}; k_proj {2:60,3:17,4:2,8:1}; v_proj {3:21,4:35,5:9,6:6,8:6,12:1,16:2}; o_proj {2:21,3:49,4:8,5:1,6:1}; gate {2:41,3:36,4:1,6:1,8:1}; up {2:18,3:57,4:3,6:1,8:1}; down {2:23,3:51,4:4,6:1,8:1}. Layer 0 gets L(q,k,v,o,gate,up,down)=3,4,16,5,8,8,6 (very sensitive first layer). Body average 1.489 bpw incl. scales; total body 13,067.5 MB, embedding 445.6 MB, lm_head 447.7 MB, norms/biases 11.5 MB (+0.45 MB files + 0.15 MB code).
* Allocation rule: minimise sum_t w_l * e_t(L_t) * n_t / N subject to sum bits = budget, where e_t(L) = Hessian-weighted relative RTN error of tensor t at L levels measured with the rotation (table in `hf/Qwen2.5-72B/sens_g128.json` [copied to `modal/sens_g128.json`]), w_l = (BI_l / mean BI)^gamma with gamma=1 and BI_l = block influence (1 - cosine(input, output) of layer l on the calibration set; stored in the same sens file under "bi"). Candidate levels {2,3,4,5,6,8,12,16}; Lagrange multiplier bisection to hit target_ratio*fp16 bytes after subtracting fixed parts (norms, files, code, embedding, lm_head).
* Group size g=128 (the 72B intermediate size 29568 is not divisible by 256), scale per group = fp16 value chosen by MSE grid search over clip factors PG=[1,.9,.8,.7,.62,.55,.5,.45,.4,.36,.32,.28,.25,.22,.19,.16,.13] x group absmax / ((L-1)/2); dequant value = (code - (L-1)/2) * scale.
* Rotation: block-diagonal Hadamard of size 128 (normalised) applied along the input dim of every weight, preceded by a random +-1 sign vector. Sign vector for layer i and group key k in {self_attn.q_proj (shared by q,k,v), self_attn.o_proj, mlp.gate_proj (shared by gate,up), mlp.down_proj}: `torch.randint(0,2,(C,),generator=torch.Generator().manual_seed(1000*i+len(k)),dtype=float32)*2-1`; head: seed key ("head", i=99999), embedding: ("emb", i=88888). The sign vectors are also stored in each `L{i}.pt` as `sg` (int8).
* GPTQ: standard column-by-column on the rotated weight with Hessian H = 2 X^T X / n from the **quantised-prefix** activations (each layer's inputs are the outputs of already quantised previous layers), damp 0.01*mean(diag H) (dead columns zeroed), block 128 lazy updates, no act-order. Calibration: ncal=256 sequences x 512 tokens.
* Embedding/lm_head: 8 levels; embedding RTN per group of 128 (rotated), lm_head GPTQ with the final-RMSNorm output Hessian; entropy accounting as for the body (emb entropy 445.6 MB, head 447.7 MB).
