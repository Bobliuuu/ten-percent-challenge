## 2. Literature (training-free compression and no-weight-training learning)
Quantization (PTQ, no gradient training): LLM.int8 (2208.07339), GPTQ (2210.17323; Hessian-based weight updates, calibration only, no backprop), SpQR (2306.03078), QuIP (2307.13304) / QuIP# (2402.04396, incoherence + E8 lattice codebooks, ~2 bit near-lossless on big LLMs), AQLM (2401.06118; multi-codebook, but its code fine-tunes codebooks/scales with backprop: grey/avoid), HQQ (mobiusml, calibration-free half-quadratic, fast, 2-4 bit), Q8BERT (1910.06188), ZeroQuant (2206.01861). Small models like BERT-base quantize worse than 7B+ LLMs below 4 bit; per-group scales (group 32-64) cost ~0.25-0.5 bit/weight, which counts against size.
Pruning: SparseGPT (2301.00774), Wanda (2306.11695): one-shot, no training; good to ~50% unstructured on LLMs, BERT tolerates ~30-50% w/o retrain, collapses beyond. Layer dropping in BERT (Poor Man's BERT 2004.03844) loses accuracy without finetune, though top-layer drop on a 2-class task loses little only with retraining.
Sparse+low-rank, codebooks/weight sharing, entropy coding: combine with quantization; entropy-code (Huffman/ANS) quantized ints for another ~10-20% free (weights are bell-shaped), lossless so rule-safe. Bit-exact lossless compression of fp weights (e.g. ZipNN-style exponent coding) gets only ~33% so insufficient alone.
Merging (TIES 2306.01708, soups 2203.05482): needs several models; irrelevant to shrinking one model.
Task-specific vocab trimming: BERT-base word embedding = 30522x768 = 23.4M params = 21% of the 110M; position emb 0.4M. Dropping unused wordpieces is exact (no weights altered, only rows deleted). Largest free win. Risk: held-out text hits removed tokens; either keep tokens needed to cover the char set/common words or re-tokenize with trimmed vocab (changes tokenization slightly: validate on dev).
Classification tricks: only the [CLS]/pooler path matters; the last layer's non-CLS outputs (FFN + attention-out for non-CLS rows) are computable only for CLS: you can prune the last layer's FFN computation to the CLS position (exact, saves compute not storage). Pooler (768x768) is needed. Heads can be zero-pruned by magnitude/importance (Michel et al. "Are sixteen heads really better than one" 1905.10650: removing many heads w/o retraining costs little).
Continual learning without weight training: kNN-LM style memory (1911.00172), kNN/cache adapters (Tip-Adapter 2207.09519, training-free), GRACE (2211.11031: lifelong editing with a codebook of keys/values at a layer, weights untouched, strong locality: best structural fit for "learn new, keep old"), SERAC (2206.06520, external edit memory + gate), ROME/MEMIT (2202.05262, 2210.07229: rank-one weight edits, closed-form, no gradients but they edit weights: check with author), ActAdd/steering (2308.10248), in-context/retrieved examples (works poorly for BERT encoders). Bloom/lexicon residual: store word->sentiment-polarity correction table.

## 3. Choosing base/task and defensibility
Numbers: textattack/bert-base-uncased-SST-2 fp32 ~438 MB, 10% = ~44 MB. 4-bit group-wise on all weights ~ 14-15% (incl. embeddings), so plain 4-bit alone FAILS. Budget sketch (bytes): trim vocab 30522 -> ~8-12k (embedding 23.4M -> ~7M), encoder 85M at ~3.3 bits incl. scales = 35 MB, embed 4-bit ~3.5MB, plus memory/tokenizer/code. Feasible with entropy coding or 3-bit + outlier channels, but needs measured accuracy; BERT at 3 bit PTQ with no training typically loses accuracy, so expect to need per-channel + outlier handling (SpQR-like) or mixed precision (keep sensitive layers 4-bit, FFN down-proj 3-bit). Plan fallback: 40% structured head/FFN-neuron prune + 4-bit + entropy coding.
Base choice alternatives (ranked for ease/defensibility):
 1. Multilingual or big-vocab base sentiment model (mBERT/XLM-R-based: embeddings are 50-70% of params, e.g. XLM-R-base 278M with 192M embedding). Trimming to English wordpieces is exact and gets to ~35-40% free; 4-bit then lands ~5-6%: comfortably under 10% with margin. Defensible ("vocabulary trimming for a monolingual task"). Caveat: base accuracy on SST-2 may be lower/less standard; need a checkpoint fine-tuned on English sentiment; and judges may deem base task = multilingual. Keep task to English test set but state it.
 2. Keep bert-base SST-2 (current). Well-known, 92.x% dev, reproducible; tight budget (above).
 3. Larger model (roberta-large SST-2, 355M, ~96%): LLM-like redundancy helps 3-bit, but costlier to evaluate and per-weight sensitivity is still comparable; lower priority.
 Task: SST-2 binary with ~92-96% ceiling is forgiving, but dev has only 872 examples (SE ~0.9 pts) so "match base" should be shown as accuracy within noise AND prediction agreement with base (>=99%) on the locked exam. Use agreement as the headline: it is the cleaner notion of "same model".
Locked exam: GLUE SST-2 test labels are hidden, so carve from validation (872) or from train. WARNING (contamination): textattack's model was trained on SST-2 train, so any train-derived split is seen by the BASE (memorized, inflated, and not "unseen" for it). Use GLUE validation (not used by textattack for training; they did select by dev though, small leak) as exam, split BEFORE any work: e.g. 436 locked / 436 dev. Lock by hashing indices + commit hash before starting. Never tune on it; report one final evaluation. A stronger story: also test on an unrelated sentiment set (e.g. rotten tomatoes / IMDB / Yelp-polarity subset) for the base-vs-compressed agreement. Better locked exam: new data neither model saw (e.g. fresh set of sentences), since "never saw" is literally the rule.
Step 5 design (feedback without weights training): define "feedback" concretely: a stream of user-corrected examples from a shifted domain (e.g. product reviews / emoji slang / a new class like 'neutral' not in base). Learn via GRACE-style key->value memory on frozen CLS embeddings (nearest-key within radius overrides logits) or kNN with distance gate. Keeps old: gate radius chosen so locked-exam predictions unchanged (measure flips = 0 on locked exam and on SST-2 dev); show forgetting-free by construction + test. Memory bytes count toward the 10% (store int8/PQ keys, cap size, e.g. <=2 MB). Show learning curve: accuracy on held-out feedback-domain set vs # feedback examples, plus locked-exam score unchanged after each batch. Learning new class ('neutral') is more dramatic than fixing errors and cannot be mistaken for base capability.

## 4. Rule-gaming/disqualification risks
- "Training weights": avoid any gradient step on the compressed model: no QAT, no distillation to a student, no LoRA, no codebook finetuning (AQLM end-to-end), no learned hypernetwork. Gray: GPTQ/SparseGPT updates (Hessian solves) and ROME/MEMIT edits (weights changed without gradients). Safest: RTN/HQQ/calibration-free + row deletion + entropy coding; use calibration only from train split if GPTQ is needed, and disclose. Student distilled from the base = new trained model => likely disqualified.
- Size: count every byte needed to run: weights, scales/zero points, codebooks, tokenizer vocab, memory store, any lookup tables, any code that decodes. Measure as the actual serialized file(s) vs base's safetensors (438MB); also report parameter-count ratio and effective bits; claim both under 10% if possible (param-count view: 10% of 110M = 11M params, which pruning would have to reach; with 3-bit packed ints that is not satisfied by quantization alone, so state disk-bytes as primary and ask in issue #1; consider asking the author). Don't offload anything to the original model or an API at inference (no base weights at runtime, no teacher fallback).
- Exam: lock before starting, never choose thresholds/bit-widths on it; log hashes; single final run; also use separate dev for gate radius. Don't test against the data the base saw as "unseen".
- Feedback loop: feedback data must not include locked-exam items; memory must not store exam items; verify.
- Don't submit a lookup table/ngram solution that matches the base by memorizing exam: that's contamination.
- Submission format: complete reproducible repo + script that downloads base, builds compressed artifact deterministically, reports sizes and scores; first-complete wins, so also post early artifacts only when full pipeline (steps 1-5) is working.

## 5. Ranked experiments
1. Measure baseline & create splits: base acc/logits on SST-2 dev; fix locked split (hash committed); dev split for tuning. Compute exact bytes budget (44 MB target; aim <=40 MB).
2. Vocab trim: tokens appearing in SST-2 train + all single chars/## pieces; check dev agreement; size gain ~16 MB. Compare re-tokenization vs UNK-mapping on exam-like OOV words.
3. Weight-only PTQ sweep (RTN per-group, HQQ) on encoder at 4/3 bits, group 32/64, with mixed precision by layer sensitivity; report agreement with base. Add entropy coding (ANS/Huffman) of ints and measure real file size.
4. Structured pruning w/o retraining: head pruning by importance (Michel) and FFN-neuron pruning by activation magnitude on train calibration; combine with 3. Find Pareto at 10%.
5. Hessian-based PTQ (GPTQ) at 3 bit with train calibration if 3 insufficient; label it clearly; run SpQR-style outlier channels.
6. Step 5 prototype: GRACE/kNN memory on CLS embeddings of compressed model; feedback stream from rotten_tomatoes/yelp/emoji-slang; gate calibration on dev; verify 0 flips on locked-style check; add 'neutral' class variant.
7. Alternative base probe: XLM-R/mBERT English sentiment checkpoint with vocab trimming, to see whether it clears 10% with margin (insurance if BERT-base cannot reach 10% without training).
